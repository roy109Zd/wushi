# ITERATION 18 · 动作分组：跳跃三合一、滑铲三合一、蹲伏独立

- 日期：2026-11-02
- 触发原因：跳跃应由「起跳 + 滞空 + 落地」组成，滑铲由「启动 + 滑行 + 结束」组成，蹲伏行走是独立动作；
  这三组要同时体现在动作剧场与角色漫游里。
- 结果：三组动作各自合并为单一 clip，动作剧场 10 个按钮，漫游新增 C / X 操作。

---

## 1. 三组动作

| 组 | 组成 | 时长 | 说明 |
|---|---|---|---|
| 跳跃 | 起跳 1.33 + 滞空 2.50 + 落地 1.27 | 5.14s | 落地是 52 关节，起跳/滞空是 22 关节 |
| 滑铲 | 启动 0.83 + 滑行 2.00 + 结束 0.50 | 3.37s | 同骨架，直接串时间轴 |
| 蹲伏行走 | 独立 | 2.00s | 循环播放 |

## 2. 合并脚本的两个改动

`scripts/merge-actions.py` 现在会：

1. **自动选基底**：取节点最多的文件（跳跃用「跳跃落地」的 52 关节骨架），其余片段的轨道按**节点名称**映射上去；
2. **时间轴累加**：每段偏移 = 前面时长之和 + 0.02s 间隔；时间 accessor 写 `min/max`；
3. **原地化**：`Hips` 的 X/Z 锁为首帧，保留 Y 与旋转。

产物：

- `public/models/jump-group.glb`（53 通道、27.6MB、5.14s）
- `public/models/slide.glb`（23 通道、33.8MB、3.37s）
- `public/models/crouch-walk.glb`（23 通道、33.8MB、2.0s，循环）

旧的 `combo-slide.glb` 与 `跳跃.glb` 已移到 `assets/actions/` 归档。

## 3. 动作剧场

- 7 段 → **9 段**（点头、跳舞、直拳、翻滚、走路、奔跑、跳跃组、滑铲组、蹲伏），加待机共 10 个按钮；
- 跳跃按钮状态写「起跳·滞空·落地」，滑铲写「启动·滑行·结束」，蹲伏写「循环」；
- 展项数据与页脚同步为 09 motion clips。

## 4. 角色漫游

新增按键，与动作剧场共用同一批 clip：

| 按键 | 行为 | 用的 clip |
|---|---|---|
| W / S | 前进 / 后退 | walk / run / crouch |
| A / D | 原地转身 | — |
| Shift | 奔跑 | run |
| 空格 | 跳跃（含落地） | jump 组，5.2s |
| C（按住） | 蹲伏行走 | crouch，速度 1.2 |
| X | 滑铲（自动前冲 3.4s，速度 6.0） | slide 组 |
| Q / Esc | 退出 | — |

滑铲期间屏蔽普通移动与动画切换，结束后恢复；蹲伏时速度压到 1.2，配合循环动作。

## 5. 验证

- `npm run build` 通过；
- 无头浏览器：动作剧场按钮数 = 10，点「滑铲」状态显示「真实骨骼 · 滑铲播放中」，无控制台错误；
- 进入 Roam 后按 C+W、X 均能触发对应链路（截图时加载遮罩尚未收完，属测试环境 CPU 慢）。

## 6. 已知取舍

- 跳跃组 5.14 秒偏长（含完整落地缓冲），漫游里按一次要等落地才恢复，手感偏「重」；若要更利落，可以只取「起跳 + 滞空」并在落地前淡出；
- 滑铲是原地 clip + 代码位移，位移与动画步频未必完全对齐，需要按观感再调速度；
- 段落之间仍是硬拼接，接缝处可能有轻微跳变。
