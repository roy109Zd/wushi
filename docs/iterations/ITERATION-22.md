# ITERATION 22 · 街市排楼与传送修复

- 日期：2026-11-02
- 触发原因：街市内容太少；传送门仍然「进不去」。
- 结果：新增生成式酒楼并排成一条街；传送逻辑重写，二次进入也能立即落位。

---

## 1. 新增资产：唐式酒楼

| 资产 | 提示词要点 | 任务 | 体积 |
|---|---|---|---|
| 酒楼客栈 | 两层木构、回廊栏杆、灰瓦飞檐、檐下红灯笼、门口招牌 | 4589436 | 21.7MB |

布置方式：**加载一次，克隆成排**（`loadLandmarkRow`），两侧各三间：

```
z = +10.2   x = 23.5 / 30.5 / 37.5
z = -10.2   x = 23.5 / 30.5 / 37.5
```

高度统一 6.8，正反朝向街道。加上原来的阁楼与行道行人，街市现在有连续立面。

同时**移除了城楼门楼**（4587284）：生成结果偏红幔质感，立在街尾像舞台幕布，反而破坏街景。素材保留在 `public/models/street-gate.glb`，以后需要可以放回来。

## 2. 传送门修复

原来的实现只在「未进入漫游」时 `enter()`，已经在漫游里再点按钮会直接返回，看起来就是「没反应」。现在：

- 新增 `RoamController.teleport({x,z,heading})`：重置位置、朝向、速度、跳跃/滑铲状态，并同步相机；
- 传送门逻辑：未在漫游 → `enter(spawn)`；已在漫游 → `teleport(spawn)`；
- 落点 `(30, 0)`，朝向 -x（面向展厅门口），能看到街道两侧的连续店铺；
- 控制台会打印 `[Portal] 已传送至街市`，便于确认是否触发。

## 3. 验证

- 无头浏览器：点击传送门后 `mode=roam`、`x=30`、控制台无错误；
- 侧向截图可见两排两层酒楼、灯笼、回廊与行人，人物与建筑比例正常（角色 3.25，楼 6.8）。

## 4. 已知问题

- 街道尽头的程序化城门仍在，若需要真正的城楼，建议重新生成一版或直接用程序化门洞；
- 酒楼克隆体共享几何与材质，内存友好，但不能逐栋换色。
