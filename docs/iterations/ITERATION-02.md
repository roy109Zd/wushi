# ITERATION 02 · 动作库扩容 + 动作与材质解耦

- 日期：2026-11-01
- 触发原因：新增 4 段骨骼动作（点头同意 / 跳舞 / 翻滚 / 直拳），需要让它们和已有的三套材质自由组合，而不是「播动作就只能看素模」。
- 本轮目标：任意材质 × 任意动作，切换材质不打断正在播放的动作。

## 1. 先确认的前提

四个动作文件与三套材质文件用的是**同一份网格**：

| 文件 | 顶点 | 索引 | POSITION 指纹 |
|---|---|---|---|
| 醒狮 / 金属 / 陶瓷彩釉 | 170,884 | 591,405 | `9ab26f0b5dac` |
| 走路 / 奔跑 / 跳跃 | 170,884 | 591,405 | `9ab26f0b5dac` |
| 点头同意 / 跳舞 / 翻滚 / 直拳 | 170,884 | 591,405 | `9ab26f0b5dac` |

所以材质和动作之间只差「Surface」这一层：把当前材质的 `material` 复制到动作网格上即可，不会有顶点错位、UV 拉伸。

## 3. 动作与材质解耦的做法

### 3.1 动作模型借用当前材质

`ActionTheater.applyMaterialFrom(group)`：

1. 遍历当前材质模型的所有 mesh，取出 material（支持材质数组）；
2. 逐个 `clone()` 到动作模型对应的 mesh 上——只复制 material，**贴图仍然共享**，不额外吃显存；
3. 每次重新应用前释放上一批克隆，避免材质泄漏；
4. 在动作模型显示**之前**应用，避免第一帧闪回动作文件自带的素模表面。

### 3.2 切材质不再打断动作

`main.switchMaterial()` 去掉了原来的 `actionTheater.stop()`，改为：

- 若动作正在播：`modelManager.show(key, { immediate: true })`（跳过淡入淡出，避免两个同位置模型叠在一起），然后把新材质换到动作模型上，再把材质模型重新隐藏；
- 若动作没在播：维持原来的淡入淡出切换。

### 3.3 借出去的材质不能被缓存淘汰

`ModelManager` 新增 `protectedKey` 与 `protect(key)`：动作模型正在使用的材质，其所属 entry 不会被 LRU 淘汰，否则贴图会被 `dispose` 掉，动作模型变黑。

播放开始 / 切材质后设置保护，`stop()` 时解除。

## 6. 验证与风险

- `npm run build` 通过。
- 本轮按你的要求没有跑浏览器实测，以下两点需要在 `npm run dev` 里确认：
  1. 播「跳舞」时切到彩釉，画面是否立即变成彩釉且动作连续；
  2. 播放中切材质后再点「待机」，材质模型能否正常显示（`protect` 是否正确解除）。
- 已知代价：新增 4 个动作文件各约 33.8MB，仍是「一个动作一份完整角色」，按需加载、缓存 2 份；若要根治需要重导资产（一份带骨骼主模型 + 多套材质 + 多段 clip）。
